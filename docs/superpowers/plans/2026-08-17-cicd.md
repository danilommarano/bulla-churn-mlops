### Task 1: Fail the training pipeline when the quality gate rejects the model

**Why:** Today `register_model` sets `promoted=False` when `roc_auc < min_roc_auc` but nothing raises, so `make pipeline` exits 0 even with a bad model — the CI `ml-pipeline` job would be a no-op gate. The pure step keeps reporting promotion as data; the orchestration layer turns a rejection into a hard failure (mirrors Vertex model validation failing the run). With `raise_on_error=True` in `run_local`, a raising component makes `make pipeline` exit non-zero.

**Files:**
- Modify: `src/churn/orchestration/steps/register_model.py` (add `ModelGateError` + `require_promotion`)
- Modify: `src/churn/orchestration/dag.py:78` (`register_model_op` calls the guard)
- Test: `tests/test_orchestration.py`

```python
def test_require_promotion_raises_when_gate_rejects():
    with pytest.raises(ModelGateError):
        require_promotion({"promoted": False, "roc_auc": 0.5, "run_id": "r", "version": 1})


def test_require_promotion_passes_when_promoted():

    assert require_promotion({"promoted": True, "roc_auc": 0.8, "run_id": "r", "version": 1}) is None
```

- [ ] **Step 3: Add the guard to the pure step module**

Append to `src/churn/orchestration/steps/register_model.py`:

```python
class ModelGateError(RuntimeError):
    """Raised when the trained model fails the quality gate (roc_auc below min_roc_auc)."""


def require_promotion(result: dict) -> None:
    """Fail the pipeline if the model was not promoted (quality gate rejected it).

    The pure `register_model` step reports promotion as data; the orchestration layer
    turns a rejection into a hard failure so CI (and Vertex-style model validation)
    fails the run instead of silently shipping a bad model.
    """
    if not result["promoted"]:
        raise ModelGateError(
            f"Quality gate rejected the model: roc_auc={result['roc_auc']:.4f} "
            "below min_roc_auc; not promoted to @production."
        )
```

- [ ] **Step 4: Run the tests to verify they pass**

Run: `uv run pytest tests/test_orchestration.py -k require_promotion -v`
Expected: PASS (2 passed).

### Task 3: GitHub Actions workflow

**Why:** The runnable CI/CD. Parallel jobs for lint/test and the training pipeline; docker build validated on PRs; image published to GHCR only on merge to `main`, gated on the other jobs.

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create the workflow**

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  lint-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - name: Set up uv
        uses: astral-sh/setup-uv@v6
        with:
          python-version: "3.12"
          enable-cache: true
      - name: Install dependencies
        run: uv sync
      - name: Lint
        run: make lint
      - name: Format check
        run: make format-check
      - name: Test
        run: make test

  ml-pipeline:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - name: Set up uv
        uses: astral-sh/setup-uv@v6
        with:
          python-version: "3.12"
          enable-cache: true
      - name: Install dependencies
        run: uv sync
      - name: Run training pipeline (KFP DAG + quality gate)
        run: make pipeline

  docker-build:
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - name: Build image
        run: make docker-build

  publish:
    needs: [lint-test, ml-pipeline]
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v5
      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          file: docker/Dockerfile
          push: true
          tags: |
            ghcr.io/${{ github.repository_owner }}/churn-api:latest
            ghcr.io/${{ github.repository_owner }}/churn-api:${{ github.sha }}
```

### Task 4: Jenkinsfile (documented Cloud Build equivalent)

**Why:** The test asks for a Jenkinsfile alongside GitHub Actions. It is the enterprise self-managed CI equivalent — declarative, mirroring the same `make` targets (DRY), documented as not executed (no Jenkins server in this local/no-cloud test).

**Files:**
- Create: `Jenkinsfile`

- [ ] **Step 1: Create the Jenkinsfile**

Create `Jenkinsfile` at the repo root:

```groovy
// Enterprise self-managed equivalent of Cloud Build (Vertex AI CI/CD).
//
// Documental: this repo's CI runs on GitHub Actions (see .github/workflows/ci.yml).
// There is no Jenkins server in this local/no-cloud technical test, so this pipeline
// is not executed here. It would run on a Jenkins agent that has `uv` and `docker`
// available, reusing the SAME make targets as GitHub Actions — the Makefile is the
// single source of truth for the CI steps (DRY).
pipeline {
    agent any

    stages {
        stage('Setup')    { steps { sh 'uv sync' } }
        stage('Lint')     { steps { sh 'make lint' } }
        stage('Format')   { steps { sh 'make format-check' } }
        stage('Test')     { steps { sh 'make test' } }
        stage('Build')    { steps { sh 'make docker-build' } }
        stage('Pipeline') { steps { sh 'make pipeline' } }
    }
}
```

- [ ] **Step 2: Structural sanity check (balanced braces/stages)**

Run: `grep -c 'stage(' Jenkinsfile`
Expected: `6` (Setup, Lint, Format, Test, Build, Pipeline).

